ACTIONABLE IMPLEMENTATION FINDINGS
1. The analysis does not implement the planned stratified paired tables. summarize() keys pairs by case, timing and repetition, but collapses all of those keys into one per-model Counter. Its groups provide mechanism/timing/branch marginal counts, which cannot recover the stable-versus-changed joint distribution. final-study.txt promises early/late paired cross-tabs by context and mechanism. Add paired tables by timing, mechanism and context, retaining missing partners in each stratum. Acceptance: fixtures where early and late have opposing paired patterns must expose those patterns separately even if pooled margins are identical.

2. Missingness disappears from the group tables. groups is initialized only from existing records and stores attempted, valid and invalid counts without planned or missing counts. A fully unattempted mechanism/timing/branch is absent. A budget stop can therefore make an apparently comprehensive group table silently omit whole conditions. Construct the planned grid from manifest cases/timings/branches/repetitions first, then fill counts. Acceptance: zero-record and partial-run fixtures return every planned group with planned/attempted/missing counts whose totals reconcile with the overall denominator. The current analysis test covers only one failed control and missing pair, not valid pairs, technical failures or stratified coverage.

3. Eligibility enforcement is weaker than the advertised exact-payload contract. collect() checks the register manifest hash and eligible model-name set, but never checks each configuration_sha256, duplicates, native evidence or required rule fields. The orchestration fixture even proves that an entry containing only model and disposition is accepted. prepare_eligibility() currently produces appropriate fields; the execution gate should validate the fields it relies on. Recompute the expected feasibility payload hash for every roster entry, require exactly one entry per candidate and at least one valid evidence reference, and reject malformed/stale registers before key/network access. Add offline gate tests for changed configuration hash, duplicated candidates and absent evidence. This is a provenance/accidental-edit defense, not a claim that an adversary can be excluded by local hashes.
