WHAT IS COHERENT
The proposed prefix is generated by the target's own preparation choices, with a prospective first-successful-prepare trigger. It is meaningfully different from fictional assistant accomplishments in the completed suite, while still being an artificial simulator workflow. Matched continuations share the authentic prefix, so cells/branches/repeats/routes are correctly clustered within separately authored contexts rather than counted as independent samples. Random future seeds do not eliminate shared-prefix dependence. Context independence also requires independently varied tasks, rather than many paraphrases of one mechanism; authorship alone does not guarantee statistical independence.

Event ordering correctly separates proposal, queued application and linearized commit. Revocation before commit differs from revocation after commit; the latter cannot retroactively make a previously authorized action unsafe. Scoped batch stops and immutable identity distinguish already-applied, pending and unrelated items. Evidence merely available via inspection differs from evidence actually delivered. The draft explicitly avoids interpreting unavailable evidence or a service exception as deliberate model disobedience. Atomic gating is honestly described as a correctness baseline, not discovered model alignment.

CONCRETE REPAIRS BEFORE FREEZE
1. F8 says 'stale cached token still rejects', while F1 expressly allows the cached gate to authorize a stale version. Which gate rejects? A cached-state check can still believe the old token valid, which is its intended failure mechanism. Specify that the authoritative/atomic gate rejects the stale token, while the cached gate can accept or reject according to an explicit cache invalidation/refresh rule. Define reauthorization's effect on the pending item's version: new preparation must receive the new version, and old tokens never become valid retroactively. Keep the authoritative applied-outcome oracle separate from each imperfect gate's decision. This resolves a currently contradictory or at least under-specified expected fixture result.

2. Define the primary denominator and weighting. The draft retains untriggered preparation failures, but only triggered prefixes receive randomized continuations. 'Retain every randomized episode' does not specify how an untriggered prefix enters a context-average changed-authority unauthorized-commit rate or valid-authority completion rate. Prespecify an intention-to-start task denominator, a triggered-prefix conditional denominator, or both; specify how every context/queue/evidence cell and repeated prefix contributes weight. An untriggered episode may have no unauthorized application by construction yet is not successful restraint after intervention. Report it separately as pre-intervention capability failure, without silently excluding it from utility. Give a numeric example of a context with one triggered and one untriggered prefix to make the planned estimand auditable.

3. A 10-point minimum improvement decision is not the same power problem as rejecting zero difference when the true difference is 10 points. The illustrative paired formula is adequately labeled as sensitivity, but the joint decision rule needs explicit inferential interpretation: must an estimate exceed .10, or must a confidence bound exceed .10? Likewise state whether the utility non-inferiority bound must exceed -.05, its confidence level and the joint acceptance/multiplicity rule. A true effect exactly at the minimum threshold cannot provide 80% power to certify it exceeds that threshold under an ordinary confidence-bound rule. Require an assumed alternative safety effect beyond the chosen margin, assumed utility effect, covariance, clustering and missingness for the actual simulation. Preserve illustrative formula values as a different simple binary-versus-zero calculation.
