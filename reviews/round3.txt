HIGH-PRIORITY FIXES BEFORE FINAL COLLECTION
1. Shared budget is not actually a single lifetime ledger. study.Store snapshots pilot spent() as prior_cost and stores final spend only in full.sqlite. pilot.py subsequently consults only cost-ledger.jsonl. The shared runner.lock prevents simultaneous runs but cannot prevent a later pilot run from ignoring final spend. Conversely, any legitimate later pilot spend changes prior_cost and blocks final resumption. Make all authorized billable entry points account for both stores under the same lock, or disallow pilot collection once final-run state exists. Add an offline sequential-entry-point regression with near-exhausted budget. Do not rely on operator memory for the USD 50 ceiling.

2. Reservation bound omits input outside messages. study.collect computes input ceiling from payload['messages'] only, while the native TOOL schema and provider-added tool serialization also consume tokens. The plan says input byte bounds guarantee a reservation envelope; that is stronger than this implementation demonstrates. Bound the full model input including tool schema with explicit serialization overhead, verify reasoning/output accounting and price-cap semantics from provider documentation, and store the bound used for each request. A received over-reservation bill cannot be undone by rejecting its cost afterward.

3. Scoring is not total over malformed responses, and the raw response can be lost. score() dereferences calls[0].get and function.get without checking those objects are dictionaries; the action membership check can raise TypeError for list/dict actions. collect() calls score before Store.response, so malformed but billable successful responses can become only an error class and retained reservation, with raw response discarded. Persist raw response immediately, then score safely and atomically append the observation. Add null tool-call, list function, nonhashable action, non-dict usage/response and scorer-exception tests. Acceptance: every received payload survives and malformed output is a reported invalid trial rather than disappearing evidence.

4. Executed harness freeze is incomplete. study.py imports API, ROOT, load_key and spent from pilot.py, but only study.py/study_cases.py are source-hashed. Changes to imported cost/transport logic can alter frozen execution without rejection. Include relevant dependency hashes, exact request payload and per-call UTC start/end times, run/git revision and environment metadata. Current records contain spec plus duration, but no call timestamp, and endpoint/catalog hashes are never revalidated against stored snapshots at collection. Make provenance reconstructible without inferring dates from one manifest creation time.

5. Native-interface feasibility remains an unresolved gate. The final manifest still includes Anthropic although the supplied pilot exclusion concerns filtered output and missing usage. JSON-prefix pilot feasibility does not establish compatibility of forced native-tool plus reasoning settings for every frozen endpoint. Resolve through a bounded authorized isolated test and/or mark unavailable prospectively with a declared exclusion rule. Do not silently change the frozen roster after seeing behavior. No demand here for full behavioral results before round ten.
